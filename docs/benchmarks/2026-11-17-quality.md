## What this shows

All three models clear all eight tasks, including the cheap model. The suite
does not separate a cheap model from a frontier one, so it cannot show a
quality difference between routing choices. Every model needed a second attempt
at least once during earlier runs; `pass@2` hides that variance.

`env-port` initially tested an ambiguous reading of "PORT is set": `??` keeps an
empty string while `||` falls back to 3000. The task now states that an empty
`PORT` counts as missing, and the row above is from the re-run.

## Method

- Each task starts from a clean copy of `tests/quality/tasks/<id>/repo`.
- Run: `opencode run --standalone --model <model> <prompt>` in that copy.
- Each task and model runs 2 time(s); a task passes when any attempt passes.
- The router is disabled for these runs so the selected model is the only
  variable.
- Grading: `node verify.mjs <run-dir>`; the model never sees the verifier.
- Timeout: 180 s per run.

## Caveats

- Eight single-turn tasks; no long refactor or multi-turn session.
- The tasks are small enough to hit a ceiling, which is why all models tie.
  Harder multi-file tasks are needed to separate cheap and frontier models.
- Passing checks measure task success, not code style or review quality.
- Token cost is not recorded. Models were deepseek-flash, deepseek-v4-pro,
  and openai/gpt-6.1-sol (roughly $0.5 per full matrix).
- The router's live pass rate is not measured here. Map its recorded model
  choices onto these per-model pass rates first.

## Reproduce

```sh
bun run quality:eval
bun run quality:eval --models deepseek/deepseek-flash
```
